Passive vs. active checks

Passive checks only do what a browser or search engine does: load your homepage, request a short list of well-known file paths, and read public DNS. Anyone can run them on any public site.

Active checks (currently: probing for risky open ports such as databases and RDP) only run after you prove ownership with a DNS record or a file on the site.

Monitoring

Site owners can have riskscope re-scan daily or weekly. We email only when something gets worse: a new medium-or-higher issue, a finding whose severity went up (for example a certificate moving from 30 to 14 days from expiry), or a lower grade. Monitoring needs proof of ownership and a click on a confirmation email, so nobody can point it at someone else's site or inbox. Every email has a one-click unsubscribe. You can also opt into a weekly summary with your grade trend, new and fixed issues, and what to fix next.

Privacy

Scan results aren't stored unless you ask: ticking "Create a shareable link" saves that one report behind an unguessable link that expires (you get a private delete link), and monitoring keeps your scan history until you stop it. Shared pages are hidden from search engines. Uploaded code is processed in memory and discarded; only package names and versions are sent to OSV.dev to look up vulnerabilities. Secrets found in code are masked in the report.

Limits

An external scan can't see everything: business-logic flaws, server-side injection bugs and internal misconfigurations need an authenticated test or code review. A good grade is a healthy baseline, not a guarantee.
